# LLM + Embedding + RAG 시나리오 비교 실험 결과

**실행일**: 2026-05-16
**LLM**: DeepSeek (`deepseek-chat`)
**임베딩 모델**: `all-MiniLM-L6-v2` (Sentence-BERT, 384차원, 영어 전용)
**지식 베이스**: 가상의 회사 내부 정책 문서 5건 (2026년 3~5월 개정)

---

## 실험 설계

4가지 시나리오를 동일한 3개 질문에 대해 실행하고 결과를 비교한다.

| # | 시나리오 | 질문 처리 방식 | 문서 검색 | 임베딩 |
|---|---------|--------------|:---:|:---:|
| 1 | LLM only | 질문을 그대로 LLM에 전달 | ❌ | ❌ |
| 2 | LLM + RAG (키워드) | 키워드로 문서 검색 → 검색 결과 + 질문 → LLM | ✅ 키워드 | ❌ |
| 3 | Embedding + LLM | 임베딩으로 질문 의도 분류 → 분석 결과 + 질문 → LLM | ❌ | ✅ 의도분류 |
| 4 | Embedding + LLM + RAG | 임베딩으로 문서 검색 → 검색 결과 + 질문 → LLM | ✅ 의미검색 | ✅ 검색 |

## 질문 1: "VIP 멤버십 혜택이 무엇인가요?"

> **중요**: VIP 멤버십은 2026년 5월 신설된 프로그램으로, LLM의 학습 데이터에 존재하지 않는다.

### 시나리오 1 — LLM only ❌

**검색된 문서**: 없음

**답변**:
> 죄송합니다만, 저는 특정 서비스나 플랫폼의 VIP 멤버십 혜택에 대한 구체적인 정보를 제공할 수 없습니다. VIP 멤버십 혜택은 각 서비스 제공업체마다 다르며, 일반적으로 해당 서비스의 공식 웹사이트나 앱, 고객센터를 통해 확인하실 수 있습니다.

**분석**: LLM은 2026년 5월 신설된 VIP 멤버십 정보를 알지 못한다. 정중하게 모른다고 답변했지만, 사용자에게 도움이 되지 않는다.

---

### 시나리오 2 — LLM + RAG (키워드 검색) ✅

**검색 방법**: 키워드 매칭 (`"VIP"` 또는 `"멤버십"` 포함 문서 검색)
**검색된 문서**: 1건

**검색된 문서**:
> 2026년 5월 1일부터 VIP 멤버십 프로그램이 신설되었습니다. 연간 구매 금액 100만원 이상 고객은 자동으로 VIP 등급이 부여됩니다. VIP 혜택: 전 제품 10% 할인, 무료 배송, 전용 고객센터 운영(24시간), 신제품 우선 구매 기회 제공. VIP 등급은 매년 1월 1일 재산정됩니다.

**답변**:
> VIP 멤버십 혜택은 다음과 같습니다: 전 제품 10% 할인, 무료 배송, 전용 고객센터 운영(24시간), 신제품 우선 구매 기회 제공입니다.

**분석**: 질문에 "VIP"와 "멤버십"이라는 키워드가 정확히 포함되어 있어 문서 검색에 성공했다. LLM은 검색된 문서를 바탕으로 정확한 답변을 생성했다.

---

### 시나리오 3 — Embedding + LLM (의미 분석) ⚠️

**검색 방법**: 임베딩으로 질문 의도 분류 (문서 검색 없음)
**분류 결과**: `membership` (유사도 0.42)

**답변**:
> VIP 멤버십 혜택은 주로 **멤버십(membership)** 주제와 관련이 깊습니다. 일반적인 VIP 멤버십 혜택으로는 다음과 같은 것들이 포함될 수 있습니다:
> - **할인 혜택**: 전용 할인율이나 특별 프로모션 코드 제공
> - **포인트 적립 및 보상**: 구매 시 추가 포인트 적립, 적립률 우대
> - **무료 배송**: 조건 없이 무료 배송 서비스

**분석**: 주제 분류는 `membership`으로 올바르게 되었으나, 실제 문서를 참고하지 않아 구체적인 수치(100만원, 10%, 24시간 등)가 없는 일반적인 추측만 생성했다.

### 시나리오 4 — Embedding + LLM + RAG (완전한 RAG) ✅

**검색 방법**: 임베딩 벡터 유사도 검색
**검색된 문서**: 3건

| 순위 | 유사도 | 문서 내용 (일부) |
|:---:|:---:|---|
| 1 | 0.43 | VIP 멤버십 프로그램 신설. 연간 100만원 이상 구매 시 자동 등급. 10% 할인, 무료 배송, 24시간 고객센터... |
| 2 | 0.23 | 개인정보 보유 기간은 회원 탈퇴 시 즉시 파기... |
| 3 | 0.21 | 국내 배송은 영업일 기준 2~3일, 5만원 이상 무료 배송... |

**답변**:
> VIP 멤버십 혜택은 다음과 같습니다: 전 제품 10% 할인, 무료 배송, 전용 고객센터 운영(24시간), 신제품 우선 구매 기회 제공입니다.

**분석**: 임베딩 검색으로 VIP 멤버십 문서를 찾아냈다(유사도 0.43). 다만 영어 전용 모델이라 한국어 텍스트의 유사도 점수가 전반적으로 낮다. 그래도 가장 관련성 높은 문서를 찾아 정확한 답변을 생성했다.

> **참고**: 검색된 2~3번 문서(개인정보, 배송)는 실제로 관련이 낮지만 벡터 공간에서 상대적으로 가까웠다. `top_k=3`이 충분히 크지 않은 경우 불필요한 문서가 섞일 수 있다.

## 질문 2: "돈을 돌려받고 싶어요"

> **핵심**: 이 질문은 "환불"을 의미하지만, "환불"이라는 단어가 전혀 포함되어 있지 않다.

### 시나리오 1 — LLM only ❌

**검색된 문서**: 없음

**답변**:
> 돈을 돌려받고 싶은 상황이 이해가 갑니다. 도움을 드리기 위해 몇 가지 질문을 드리겠습니다.
> 1. **누구에게** 돈을 주셨나요?
> 2. **어떤 경로로** 지불하셨나요?
> 3. **언제, 어떤 목적으로** 돈을 지불하셨나요?

**분석**: 일반적인 고객 상담사의 역질문 패턴이다. 회사의 구체적인 환불 정책(14일 이내, 마이페이지 신청 등)은 전혀 언급하지 못한다.

---

### 시나리오 2 — LLM + RAG (키워드 검색) ❌ 실패

**검색 방법**: 키워드 매칭
**검색된 문서**: **0건**

**답변**:
> 돈을 돌려받고 싶은 상황이 이해가 갑니다. 구체적인 상황에 따라 방법이 다를 수 있습니다. 일반적인 조언을 드리자면:
> 1. **거래 내역 확인**: 언제, 누구에게, 어떤 방식으로 돈을 보냈는지 기록을 정리하세요.
> 2. **상대방과 연락**: 공식적인 연락을 통해 환불을 요청하세요.

**분석**: **이것이 키워드 검색의 치명적인 한계다.** 질문에 "환불"이라는 단어가 없어서, "환불 정책" 문서를 단 하나도 찾지 못했다. 결국 LLM only와 동일한 수준의 일반적인 답변만 생성했다. 사용자는 "돈을 돌려받고 싶다"고 했을 뿐인데, 정작 필요한 환불 정책 정보는 받지 못한다.

---

### 시나리오 3 — Embedding + LLM (의미 분석) ❌

**검색 방법**: 임베딩으로 질문 의도 분류 (문서 검색 없음)
**분류 결과**:

| 주제 | 유사도 |
|---|:---:|
| promotion | 0.12 |
| refund | 0.08 |
| privacy | 0.05 |
| shipping | 0.03 |
| membership | 0.01 |

**답변**:
> 죄송합니다만, 현재 시스템 분석 결과 귀하의 질문과 가장 관련 높은 주제는 **프로모션(0.12)**으로 나타났습니다. 하지만 이는 환불(refund) 주제(0.08)보다 약간 높은 수치일 뿐...

**분석**: 영어 전용 임베딩 모델(`all-MiniLM-L6-v2`)이 한국어 "돈을 돌려받고 싶어요"의 의미를 제대로 포착하지 못했다. `refund`(0.08)보다 `promotion`(0.12)을 더 높게 평가하는 오분류가 발생했다. 문서가 없으니 할루시네이션도 발생한다.

---

### 시나리오 4 — Embedding + LLM + RAG (완전한 RAG) ⚠️

**검색 방법**: 임베딩 벡터 유사도 검색
**검색된 문서**: 3건

| 순위 | 유사도 | 문서 내용 (일부) |
|:---:|:---:|---|
| 1 | 0.23 | 개인정보 보유 기간은 회원 탈퇴 시 즉시 파기... |
| 2 | 0.23 | VIP 멤버십 프로그램 신설... |
| 3 | 0.21 | 국내 배송은 영업일 기준 2~3일... |

**답변**:
> 죄송합니다. 제공된 문서에는 환불(돈을 돌려받는) 절차에 대한 내용이 포함되어 있지 않습니다. 관련 정보를 알 수 없어 도움을 드리기 어렵습니다.

**분석**: **임베딩 검색도 실패했다.** 영어 전용 모델이 한국어 표현 "돈을 돌려받고"와 "환불" 문서 간의 의미적 연결을 만들지 못했다. 검색 결과 상위 3건 중 환불 문서는 하나도 없다. 최소한 LLM이 "모른다"고 정직하게 답변한 것은 할루시네이션보다 낫다.

> **개선 방향**: `intfloat/multilingual-e5-large` 같은 다국어 임베딩 모델을 사용하면 한국어 의미 검색 정확도가 크게 향상된다.

## 질문 3: "개인정보는 얼마나 보관되나요?"

> **중요**: 개인정보 보관 기간은 법령에 따라 계약 5년, 결제 5년, 분쟁 3년으로 상이하다. LLM이 이를 정확히 알 가능성은 낮다.

### 시나리오 1 — LLM only ❌

**검색된 문서**: 없음

**답변**:
> 개인정보 보관 기간은 서비스의 종류와 해당 정보를 수집한 목적에 따라 다릅니다. 일반적으로 개인정보는 수집 목적이 달성된 후에는 지체 없이 파기되며, 법령에 따라 일정 기간 보관해야 하는 경우에는 해당 법령에서 정한 기간 동안만 보관됩니다.

**분석**: 일반론만 말할 뿐, 구체적인 보관 기간(5년, 3년)을 전혀 언급하지 못한다.

---

### 시나리오 2 — LLM + RAG (키워드 검색) ❌

**검색 방법**: 키워드 매칭
**검색된 문서**: **0건**

**답변**:
> 개인정보 보관 기간은 해당 정보를 수집한 목적과 관련 법령에 따라 다릅니다. 일반적으로 개인정보는 수집 목적이 달성된 후에는 지체 없이 파기되며...

**분석**: 질문에는 "개인정보"가 있고 문서에도 "개인정보"가 있지만, **한국어 형태소 분석 없이 단순 substring 매칭**을 하기 때문에 "개인정보는"과 "개인정보"가 매칭되지 않았을 가능성이 있다. 실제로 `_keyword_search` 함수의 `re.findall(r"[\w가-힣]+", query)` 정규식으로 추출한 키워드와 문서 텍스트 간 매칭이 실패했다.

---

### 시나리오 3 — Embedding + LLM (의미 분석) ❌ 위험

**검색 방법**: 임베딩으로 질문 의도 분류 (문서 검색 없음)
**분류 결과**: `privacy` (유사도 0.21)

**답변**:
> 회원님의 개인정보 보관 기간에 대해 문의해 주셨네요. 저희 서비스에서는 **회원 탈퇴 시 즉시 파기**를 원칙으로 하며, 관련 법령에 따라 일부 정보는 일정 기간 보관 후 안전하게 삭제됩니다.

**분석**: **할루시네이션이 발생했다.** 주제 분류는 `privacy`로 맞았지만, 문서를 참고하지 않아 "회원 탈퇴 시 즉시 파기"라는 일부만 맞고 전체가 틀린 답변을 생성했다. 법령별 보관 기간(5년, 3년)을 전혀 언급하지 못하고 "이용약관을 참고하라"는 책임 회피성 답변으로 끝난다. 이런 답변을 사용자에게 그대로 보여주면 신뢰를 잃을 수 있다.

---

### 시나리오 4 — Embedding + LLM + RAG (완전한 RAG) ✅

**검색 방법**: 임베딩 벡터 유사도 검색
**검색된 문서**: 3건

| 순위 | 유사도 | 문서 내용 (일부) |
|:---:|:---:|---|
| 1 | 0.42 | 개인정보 보유 기간은 회원 탈퇴 시 즉시 파기... 계약 5년, 결제 5년, 분쟁 3년... |
| 2 | 0.41 | 국내 배송은 영업일 기준 2~3일... (관련성 낮음) |
| 3 | 0.37 | 환불 정책 v3.2... (관련성 낮음) |

**답변**:
> 개인정보 보유 기간은 회원 탈퇴 시 즉시 파기하는 것을 원칙으로 합니다. 단, 관련 법령에 따라 계약 또는 청약 철회에 관한 기록은 5년, 대금 결제 및 재화 공급 기록은 5년, 소비자 불만 또는 분쟁 처리 기록은 3년 동안 보관됩니다.

**분석**: 임베딩 검색으로 개인정보 문서를 정확히 찾아냈다(유사도 0.42). LLM은 문서의 구체적인 보관 기간을 그대로 인용하여 정확한 답변을 생성했다. 할루시네이션 없이 문서 기반的事实을 전달한다.

| **키워드 RAG** | 구현 쉬움, 정확한 키워드 매칭 시 강력 | "돈을 돌려받고" → "환불" 같은 의미 연결 불가 |
| **Emb + LLM** | 질문 의도 파악 가능 | 문서 없이 추측 → 할루시네이션 발생 |
| **Full RAG** | 의미 검색 + 문서 기반 정확한 답변 | 임베딩 모델 품질에 의존, 한국어는 모델 선택이 중요 |

---

## 결론 및 교훈

### 1. RAG는 필수다
LLM만으로는 내부 정책, 최신 정보, 특정 도메인 지식을 다룰 수 없다. 문서 검색을 통한 RAG는 선택이 아닌 필수다.

### 2. 키워드 검색만으로는 부족하다
"돈을 돌려받고 싶어요" → "환불" 같은 자연스러운 표현 차이를 키워드 검색은 전혀 처리하지 못한다. 사용자는 회사 내부 용어로 질문하지 않는다.

### 3. 임베딩 모델 선택이 성능을 좌우한다
`all-MiniLM-L6-v2`는 영어 전용 모델이다. 한국어 서비스에 사용하면 의미 검색이 부정확해진다. 다국어 모델(`multilingual-e5-large`, `BGE-M3`)이나 한국어 특화 모델(`ko-sroberta-multitask`)을 선택해야 한다.

### 4. "모른다"는 답변이 할루시네이션보다 낫다
시나리오 4에서 검색된 문서에 환불 정보가 없을 때, LLM은 "제공된 문서에 해당 내용이 없습니다"라고 정직하게 답변했다. 시나리오 3처럼 그럴듯하게 지어내는 것보다 훨씬 안전하다.

### 5. 실제 서비스 적용을 위한 체크리스트

- [ ] 다국어 임베딩 모델로 교체 (`intfloat/multilingual-e5-large` 권장)
- [ ] 문서 청킹(chunking) 전략 수립 (문서당 500~1000자)
- [ ] 벡터 DB 도입 (FAISS, Chroma 등)
- [ ] 검색 품질 메트릭 설정 (MRR, NDCG)
- [ ] 사용자 피드백 루프 구축 (검색 결과 평가 → 모델 파인튜닝)
